# Freedom CQA: AI Pipeline v1.4

Итерация cqa-assessment-1.4 подготовлена в feature/ai-pipeline. Автоматические тесты используют только моки; реальные проверки выполнялись отдельно по явному разрешению на синтетических данных. Ключи и временные JSON-отчёты не входят в исходники.

## Что уже было готово

`web/preprocess.js` проверяет исходный диалог, роли, ID, положительную версию чек-листа, шкалы и правила N/A. Создаёт маскированный пакет с полным контекстом, кандидатами доказательств и fingerprints исходника/чек-листа. `worker/assessment.mjs` уже содержал мастер-промпт, строгую динамическую схему и validateAssessment. `web/domain.js` содержит восемь критериев и calculate. API и интерфейс уже умеют принимать результат, проверять актуальность и хранить историю. Локальные настройки используют same-origin, CSRF и атомарное сохранение ключа.

## Изменения и последовательность

1. POST /api/assess принимает существующий контракт `{conversation, criteria, checklistVersion}`. Переданный клиентом packet не используется: сервер заново собирает пакет из исходных данных.
2. Проверяются диалог и переданная актуальная конфигурация чек-листа; версия и fingerprints возвращаются с результатом. Сервер не имеет отдельного реестра версий: источник активной версии — существующее приложение. Защита от изменения диалога остаётся в интерфейсе; перед установкой результата installAssessment также проверяет актуальные criteria/version. Изменившийся активный чек-лист отклоняет результат до изменения ответов, истории и апелляций.
3. `buildAssessmentRequest` строит схему по текущим типам, шкалам и N/A. `worker/gemini.mjs` преобразует её в Gemini REST generateContent: systemInstruction, contents и generationConfig с responseMimeType=application/json и responseJsonSchema. Ключ передаётся заголовком x-goog-api-key, не URL.
4. Ответ ограничен 2 МиБ. Блокировка, незавершённая генерация, невалидный JSON, лишние поля, недопустимые значения, пустые или неизвестные evidence ID отклоняются. Без валидного результата API возвращает ошибку, а не оценку для сохранения.
5. `calculate` программно нормализует оценку с исключением N/A и flag. Грубая ошибка возвращается отдельно в critical. Модель не рассчитывает баллы.
6. Существующие поля результата сохранены: conversationId, answers, criteria, version, sourceFingerprint, checklistFingerprint, finalScore, critical, assessment. В assessment.provider теперь поддерживается gemini; сравнение с эталоном принимает этот источник.

## Мастер-промпт и чек-лист

Мастер-промпт: экспорт ASSESSMENT_INSTRUCTIONS в `worker/assessment.mjs`, версия cqa-assessment-1.4. Добавлены правила для казахских отрицаний, смешанного языка и различия между запросом и подтверждением идентификации. Существующие правила оценки только оператора, защиты от инструкций внутри диалога, исключений и доказательств сохранены.

Оценка выполняется одним запросом: применимость → значение → evidence → reason. Дерево выявления потребности выбирает N/A при достаточных исходных данных, true при необходимом выполненном уточнении и false при пропущенном. N/A требует evidence исходной реплики клиента. Девять RU/KZ/EN примеров не взяты из бенчмарка.

Семантические пояснения применяются только при точном совпадении title, description, type, scale, allowNA и naRule с исходной конфигурацией. ID служит ключом результата: переименование не меняет смысл. Изменённые определения отключают старые пояснения. Critical, management, полнота консультации, идентификация и эмпатия проверяются по самостоятельным основаниям.

Gemini-схема использует anyOf для всего ответа каждого критерия: применимая ветвь запрещает null и not_applicable; ветвь N/A разрешена только при allowNA=true и требует value=null и evidenceKind=not_applicable. required, additionalProperties=false и minItems=1 сохраняются. Непустой reason задаётся инструкцией и проверяется validateAssessment: неподдерживаемый minLength не передаётся. Сервер не исправляет смысловые оценки автоматически.

Используется текущая конфигурация `web/domain.js`: веса 10/15/20/20/15/15/5/0; шкала консультации 0/5/10/15/20; управления 0/4/7/10. N/A разрешено только условиями каждого критерия. Отдельного официального документа Freedom Broker в репозитории нет: соответствие конфигурации официальному документу требует ручной сверки. Внешние процедуры компании не выдумываются.

## Ожидаемый JSON модели

```json
{
  "answers": {
    "contact": {"value": true, "reason": "Оператор поздоровался и представился.", "evidence": [2], "evidenceKind": "present"},
    "need": {"value": null, "reason": "Клиент сразу сообщил все необходимые сведения.", "evidence": [1], "evidenceKind": "not_applicable"},
    "identity": {"value": null, "reason": "Общая справка не требует проверки личности.", "evidence": [1,2], "evidenceKind": "not_applicable"},
    "solution": {"value": 20, "reason": "Оператор ответил на единственный вопрос.", "evidence": [1,2], "evidenceKind": "present"},
    "empathy": {"value": true, "reason": "Ответ вежливый, недовольство не выражено.", "evidence": [1,2], "evidenceKind": "present"},
    "management": {"value": 10, "reason": "Инструкция понятна и последовательна.", "evidence": [2], "evidenceKind": "present"},
    "closing": {"value": false, "reason": "Оператор закрыл чат без прощания.", "evidence": [2,3], "evidenceKind": "absence"},
    "critical": {"value": false, "reason": "В проверенном диалоге грубых нарушений нет.", "evidence": [1,2,3], "evidenceKind": "absence"}
  }
}
```

Это пример формы, а не ответ для произвольного диалога: все ID должны существовать во входе. Список ключей и допустимых значений строится из активного чек-листа. value=null требует not_applicable; для других значений not_applicable запрещён. reason — конкретное объяснение на русском. Внешние поля вроде finalScore не разрешены.

## Лимиты и ошибки

Адаптер допускает два одновременных запроса, 15 запросов за скользящую минуту, 500 за скользящие 24 часа. Входные токены резервируются консервативной верхней оценкой по UTF-8 байтам всего тела запроса в пределах 250 000/мин. Это намеренно строже обычной оценки токенизатором; неиспользованный резерв не возвращается. Проверка модели также расходует локальный слот запроса. При превышении локального лимита возвращается 429 без сети.

HTTP 429 устанавливает общую паузу с учётом Retry-After (секунды или HTTP date), по умолчанию 60 секунд. Автоповторов нет, включая суточную квоту. Ошибки авторизации, недоступной модели, сети и timeout возвращаются без сырого тела провайдера и ключа. POST /api/ai/verify проверяет доступ к модели без генерации и без транскрипта.

Ограничитель действует только в одном процессе/Worker isolate и сбрасывается после перезапуска. Несколько серверов не делят квоту. Для общего строгого лимита при масштабировании нужен централизованный постоянный счётчик. Реальные лимиты проекта и расход вне приложения проверяются в Google AI Studio.

Эти два теста не подтверждают общую точность v1.4. Временные отчёты не публикуются.

## Стабилизация перед интеграцией

Единственная пустая/пробельная реплика оператора больше не позволяет запустить оценку: preprocessing возвращает no_operator_text, packet=null, assess — PREPROCESS_BLOCKED/422 без LLM. Нормализованные пустые system/client сообщения и пустые сообщения рядом с содержательными operator сохраняются как контекст.

Три ограничения размеров/квот различаются:

- Сырой HTTP JSON ограничен 600 000 байт; preprocessing — 200 000 символов и 5 000 реплик. Это разные единицы измерения.
- Подготовленное тело Gemini, включая промпт, схему и transcript, резервируется по UTF-8 байтам. Это консервативный локальный бюджет, а не измеренный провайдером расход токенов. Если один запрос превышает 250 000 байт, возвращается GEMINI_INPUT_TOO_LARGE/413 без сети и без расхода квоты. Ожидание не исправит такой пакет. Лимит не увеличен, контекст не обрезается.
- Временное суммарное ограничение локального limiter остаётся 429; реальный HTTP 429 Gemini также сохраняется с сообщением провайдера об ограничении и cooldown. Различаются местом возникновения и безопасным сообщением; сырой ответ провайдера не раскрывается. Автоповторов нет.

Установка оценки теперь получает текущие criteria/version из интерфейса. Даже если результат соответствует отправленному старому снимку, смена активного чек-листа запрещает тихое сохранение. Сравниваются канонические поля определения, веса, шкалы и N/A, независимо от порядка свойств объекта. Формат AI-результата, старые оценки и история сохранены.

В рабочем окружении автора ветки локальный `.env` был настроен на gemini-3.5-flash-lite без изменения строк ключей; там localhost подтвердил provider=gemini и нужную модель. Эти настройки и ключи не переносятся через Git. Переменные родительского процесса имеют приоритет над `.env`: если при другом запуске модель отличается, уберите устаревшее переопределение в окружении запуска либо задайте GEMINI_MODEL=gemini-3.5-flash-lite явно для процесса. Секрет не возвращается GET /api/ai/config.

Публичная авторизация в эту стабилизацию не входит. Для опубликованного Worker с ключом по-прежнему необходим согласованный внешний контроль доступа; локальный сервер остаётся на 127.0.0.1. Реальные клиентские данные требуют отдельной процедуры обезличивания.

## Дополнительный провайдер Groq

Адаптер `worker/groq.mjs` использует только https://api.groq.com/openai/v1/chat/completions. `AI_PROVIDER=groq` выбирает его явно; При отсутствии явного выбора используется уже настроенный ключ; для чистой установки без ключей — Gemini. Автоматического fallback нет. Настройки Gemini и Groq хранятся раздельно, старый ключ при смене провайдера не удаляется.

```dotenv
AI_PROVIDER=groq
GROQ_API_KEY=полный_ключ_вашего_проекта
GROQ_MODEL=openai/gpt-oss-120b
```

После ручного изменения .env перезапустите локальный сервер; переменные процесса имеют приоритет. Для возврата установите AI_PROVIDER=gemini и перезапустите. Не удаляйте GEMINI_API_KEY/GEMINI_MODEL. Рабочий .env при реализации Groq не изменялся.

Сохраняются cqa-assessment-1.4, маскированный packet, validateAssessment, evidence и calculate. Groq получает Chat Completions messages (system/user), response_format=json_schema со strict=true, stream=false, max_completion_tokens=8192 и reasoning_effort=medium. Схема содержит закрытые объекты, все обязательные поля и связанные anyOf-ветви применимости. Непустые reason/evidence и существование ID проверяются сервером. JSON Object fallback и tools не используются.

Groq документирует strict mode для openai/gpt-oss-120b, но принятие нашей конкретной схемы требует первого отдельно разрешённого реального теста. Документация: https://console.groq.com/docs/structured-outputs и https://console.groq.com/docs/model/openai/gpt-oss-120b.

HTTP 429 учитывает Retry-After и временно блокирует новые запросы; HTTP 503, авторизация, ошибки формата, незавершённые ответы, refusal и таймауты возвращаются без сырых тел и секретов. Автоповторов нет. Ответ ограничен 2 МиБ; таймаут оценки — 120 с, проверки доступа — 20 с. Независимый limiter Groq допускает два одновременных запроса в одном процессе; RPM/TPM/RPD зависят от аккаунта и не копируются с Gemini. Квота Gemini от запросов Groq не расходуется.

POST /api/ai/verify проверяет модель через Groq Models GET без транскрипта и генерации; это не проверка принятия JSON Schema. В окне подключения используются прежние элементы интерфейса, меняются только подписи активного провайдера и валидация имени модели с `/`. Сравнение с эталонами принимает provider=groq.

Автоматические проверки Groq — только моки: строгая схема, все восемь критериев, динамические шкалы и N/A, ошибки evidence, подсчёт баллов, критический флаг, metadata, маскирование, маршрутизация провайдеров, 429/503/timeout, некорректные и слишком большие ответы, сохранение раздельных ключей и исполнение Worker bundle. Точность GPT-OSS 120B не измерялась.

## Ключ и ручная проверка

В локальном `.env` (он исключён из Git):

```dotenv
GEMINI_API_KEY=полный_ключ_вашего_проекта
GEMINI_MODEL=gemini-3.5-flash-lite
```

Либо сохраните ключ в существующем окне подключения ИИ. Не вставляйте ключ в исходники, чат, экспорт или frontend. Сохранение через настройки создаёт файл с правами 0600. На хостинге задайте серверные секреты. Старые OPENAI-переменные сохраняются. Явный AI_PROVIDER имеет приоритет; без него первый доступный ключ выбирается в порядке OpenAI → Gemini → Groq. Это сохраняет существующие подключения после обновления. Для Gemini при наличии старого ключа OpenAI задайте AI_PROVIDER=gemini. Неизвестный провайдер блокируется с INVALID_PROVIDER. Автоматического перехода к другому провайдеру после ошибки запроса нет.

Вручную: сверить официальный чек-лист, проверить бесплатную квоту и доступность модели, проверить окно подключения и одну синтетическую оценку RU/KZ/EN, доказательства и сохранение после изменения чек-листа. Сначала использовать только синтетику. Маскирование существующего preprocessing не гарантирует полного обезличивания свободного текста; реальные клиентские данные во внешнюю LLM не отправлять без отдельной процедуры обезличивания.

Документация: [Gemini structured outputs](https://ai.google.dev/gemini-api/docs/structured-output), [generateContent](https://ai.google.dev/api/generate-content), [модель](https://ai.google.dev/gemini-api/docs/models/gemini-3.5-flash-lite).
