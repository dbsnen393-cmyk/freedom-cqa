# Freedom CQA

Рабочий веб-прототип контроля качества диалогов для хакатона.

## Запуск

Нужен Node.js 20 или новее, установка зависимостей не требуется.

    node server.mjs

Откройте http://localhost:4173. На этом компьютере подключение уже настроено в локальном .env. Для переноса создайте .env по образцу .env.example и добавьте ORGANIZER_API_URL из Student Guide. Ссылку с подписью доступа не помещайте в клиентский код или Git.

## Что работает

- Получение DEV из API организаторов: 60 чатов и 5 звонков, RU/KZ/EN.
- Обновление без дублей; выбор group_id для нового контрольного набора.
- Отдельные источники DEV, демонстрационные примеры и импорт JSON.
- Поиск, фильтры языка, канала и статуса, сортировка и страницы по 12 записей.
- Участники: 01 оператор, 02 клиент, 03 бот; системные события отдельно. API содержит роли, но не идентификаторы отдельных людей, поэтому это нумерация ролей, не распознавание голосов.
- Реплики имеют порядковый номер, стабильный ID conversation_id:M0001 и исходную метку времени. ISO-время преобразуется в секунды относительно первого события, исходное значение сохраняется.
- Встроенный плеер звонков, скорость, перемотка, подсветка текущей реплики и участника, автопрокрутка внутри транскрипта. Нажмите таймкод реплики, чтобы перейти к ней.
- Чаты можно просматривать по временному таймлайну без аудио.
- Настройка синхронизации: сдвиг в секундах, необязательное исключение системных пауз записи. Положительный сдвиг означает, что аудиофайл начинается позже начала транскрипта. Формула: позиция аудио = время реплики − исключённые паузы − сдвиг.
- Чек-лист из 8 критериев, редактирование, версии, апелляции и пересчёт финальной оценки.
- Сохранение состояния в браузере и экспорт JSON. Изменённый транскрипт сбрасывает старую оценку; предыдущая оценка и апелляции сохраняются в архивных полях экспорта.

## Точность синхронизации

Подсветка следует предоставленным таймкодам до следующей реплики. Источник не предоставляет отдельные интервалы окончания речи или точную разметку по словам. Паузы записи по умолчанию не вычитаются: включайте эту настройку только после проверки конкретного аудио. Речь может перекрываться, исходные транскрипты содержат ошибки распознавания. Это не автоматическое выравнивание текста по звуковой волне.

## Границы текущей версии

Подключение OpenAI реализовано. Для реальных оценок требуется собственный API-ключ. До явного запуска диалоги остаются без оценки; демонстрационная разметка видна только в источнике «Демопримеры». Для сравнения с Ground Truth доступен раздел «Проверка точности». Точность реальной модели ещё не измерялась: для этого нужны её ответы и независимые эталоны.

Состояние и ручные решения хранятся в localStorage конкретного браузера, общей базы между пользователями пока нет. Изменение набора из API сохраняется при нажатии «Обновить набор»; автоматического фонового опроса нет. Срок доступа к API зависит от организаторов.

## Серверные маршруты

- GET /api/status — готовность подключения.
- GET /api/datasets?group_id=DEV&refresh=1 — свежий набор; подписи исходных ссылок удалены из ответа.
- GET /api/audio?group_id=DEV&conversation_id=... — аудио конкретного диалога с поддержкой HTTP Range.

Сервер раскрывает страницу плеера организаторов и получает аудиопоток с разрешённого домена. Произвольные адреса передавать нельзя. В памяти временно хранится одна запись, до 28 МБ. Секрет API находится в окружении локального сервера и приватного хостинга. Транскрипты не включены в исходники или сборку.

## Структура

- web/ — исходный HTML, стили и JavaScript интерфейса.
- web/timeline.js — нормализация времени, участников и синхронизация данных.
- web/playback.js — плеер и подсветка транскрипта.
- worker/api.mjs — серверное подключение к API и аудиопрокси.
- server.mjs — локальный сервер без зависимостей.
- build.mjs — сборка серверной версии для Sites в dist/.
- checks/ — проверки формулы, таймлайна, обновлений и аудиопрокси.

## Проверки и сборка

    node --test checks/*.test.mjs
    node build.mjs

Автоматические проверки запускаются командой node --test checks/*.test.mjs. В браузере дополнительно проверяются фактическая загрузка DEV, аудио и переход к реплике.

## Подготовка перед ИИ (v0.3)

В списке диалогов нажмите «Подготовить набор» или откройте диалог → «Подготовка к ИИ» → «Подготовить диалог». Отчёт показывает объективные показатели, кандидаты доказательств и полный пакет для будущей модели. Кнопка с номером реплики открывает исходный фрагмент; пакет можно посмотреть и скачать как JSON.

Конвейер:
1. Проверка ID, ролей, языка, таймкодов, структуры и актуального чек-листа.
2. Нормализация Unicode и переносов без исправления смысла или ASR. Исходная запись в браузере не меняется; повторы, системные сообщения и короткие ответы сохраняются.
3. Сбор статистики ролей, последовательных блоков, первого/последнего ответа оператора и справочных интервалов чата.
4. Маскирование уверенно распознанных email, телефонов, ИИН по контексту, карт, счетов, OTP/CVV, паролей и секретных ссылок. Одинаковое значение получает постоянную маску внутри диалога. Имена, адреса и необычные форматы могут остаться; полной анонимизации механизм не гарантирует.
5. Поиск кандидатов доказательств RU/KZ/EN по исходным восьми критериям. При изменении смыслового определения критерия его старая эвристика отключается. Бот не получает заслуги оператора; маркеры не становятся автоматическими оценками или N/A.
6. Сбор всего замаскированного транскрипта, текущей версии чек-листа, фактов и кандидатов в пакет. Служебные ссылки API/аудио, прежние оценки и апелляции исключены. Отпечатки SHA-256 позволяют отличать версии текста и чек-листа.

Предварительный разбор выполняется без LLM и внешних запросов. Он не доказывает правильность консультации, успешную идентификацию или наличие грубой ошибки. Для этих решений модель должна проверить полный контекст. Порог первого ответа 3 минуты, теги и вложения исключены из оценки по условиям хакатона. Время речи, тишина и перебивания не вычисляются, потому что границы окончания речи неизвестны.

Браузерный кэш отчётов живёт до обновления страницы и автоматически перестаёт использоваться после изменения текста или чек-листа. Загрузка реальных диалогов и ручные решения сохраняются как прежде. Подготовка сама не вызывает модель. Финальная оценка запускается отдельной кнопкой «Оценить GPT».

### Использование из кода

    import {preprocessConversation} from './web/preprocess.js';
    const {report, packet} = await preprocessConversation(conversation, currentCriteria, checklistVersion);

packet=null означает блокирующую ошибку. report.status: prepared / review / blocked. Поле reviewRequired у кандидатов всегда true. Название prepared означает техническую подготовку пакета, а не сертификацию анонимности или качества работы оператора.

Тот же движок доступен серверу:

    POST /api/preprocess
    Content-Type: application/json
    {"conversation": {...}, "criteria": [...], "checklistVersion": 1}

Ответ 200 — пакет подготовлен, 422 — ошибки данных, 400 — неверный запрос, 413 — превышен размер. Максимум: 600 КБ запроса, 5 000 реплик, 200 000 символов текста и 100 критериев. Слишком большой диалог блокируется целиком, без отправки усечённого контекста. Этот маршрут сам не вызывает AI.

Для пакетной подготовки файла с исходным стандартным чек-листом v1:

    node scripts/prepare-dataset.mjs --input ../data/dev-dataset.json --output ../data/DEV.prepared.json

При запуске из D:\Freedom-CQA\project результат сохранён в D:\Freedom-CQA\data\DEV.prepared.json: 65 диалогов, 1 268 реплик, 44 исходных маски. Новых уверенно распознанных значений на этом наборе не найдено; это не гарантия отсутствия других персональных данных.

Новые модули: web/preprocess.js, web/privacy.js, web/preparation-ui.js. В worker/api.mjs используется тот же движок, build.mjs включает его в серверную сборку. Проверки включают обход маскирования через псевдозаглушки и метаданные.


## Оценка GPT и апелляции (v0.4)

В локальной версии откройте «Подключить GPT» в верхней панели. Введите API-ключ OpenAI, при необходимости измените модель (по умолчанию gpt-5.4), сохраните и проверьте доступ. Ключ сохраняется сервером в локальном .env, не возвращается в браузер, не попадает в localStorage, экспорт или Git. Пустое поле ключа при сохранении оставляет прежний ключ. На опубликованной версии ключ задаётся отдельно как серверный секрет OPENAI_API_KEY; OPENAI_MODEL выбирает модель. Локальный ключ автоматически на хостинг не переносится.

Откройте диалог и нажмите «Оценить GPT». Сервер заново подготавливает полный контекст, маскирует распознаваемые персональные значения и отправляет пакет через Responses API со строгой JSON-схемой. Старые оценки и апелляции не входят в запрос. Ответ проверяется по допустимым значениям, N/A и существующим номерам реплик. Итог и критический флаг вычисляются кодом. store:false используется для ответа; это не обещание отсутствия всех журналов у провайдера. Автоматических повторов оплачиваемого запроса нет.

Маршруты: GET /api/ai/config (состояние без ключа), POST /api/ai/config (только локальные настройки с Origin и CSRF), POST /api/ai/verify (проверка доступа к модели без диалога), POST /api/assess с телом {conversation,criteria,checklistVersion}. Реальный запрос требует действующий ключ и доступ к модели. Автотесты используют подменённого провайдера и не проверяют качество настоящих оценок.

Нажатие на всю реплику или Enter/пробел выбирает её и переходит к таймкоду. Выбранная реплика и текущий говорящий выделяются отдельно. «Апелляция» у сообщения открывает выбор критерия и прикладывает номер реплики. Рассмотрение показывает основания модели и приложенную реплику. Повторная оценка архивирует прежние апелляции и сохраняет историю: старое ручное решение не меняет новую оценку.

Документация API: https://developers.openai.com/api/docs/guides/structured-outputs?api-mode=responses и https://developers.openai.com/api/docs/models/gpt-5.4.


## Эталоны и проверка без GPT (v0.5)

Раздел **Проверка точности** содержит два независимых режима: сравнение рабочих оценок с эталонами и учебную проверку интерфейса. Всё выполняется локально в браузере; эти действия не обращаются к модели.

### Эталонные оценки

1. Загрузите диалоги из API или JSON. Для рабочего сравнения нужны реальные диалоги, а не демонстрационные примеры.
2. Создайте ручной эталон в интерфейсе или скачайте шаблон JSON, заполните значения и импортируйте файл. Официальный формат Ground Truth организаторов не опубликован; формат ниже является форматом нашего сервиса.
3. Сравните исходный ответ модели или итог после апелляций. Для исходной точности учитываются только ответы с провайдером OpenAI; учебные результаты исключены.

Формат: `{ "schema": "freedom-cqa-reference-v1", "records": [...] }`. Каждая запись содержит `conversationId`, `source`, `sourceFingerprint`, `checklistFingerprint`, `version`, полный `criteria`, `answers`, `kind` и `label`. Ответы — объект `criterionId: value`: `true`/`false`, число из разрешённой шкалы или `null` только для допустимого N/A. Строка `__UNLABELED__` в шаблоне означает **не заполнено**, её необходимо заменить. Не заменяйте её автоматически на `null`. Для ручной разметки `kind: "manual"`, для независимого загруженного эталона — `"ground_truth"`. Это описание происхождения, а не подтверждение качества эталона.

Шаблон содержит отпечатки выбранных текста и чек-листа; не редактируйте их вручную. Импорт проверяет весь файл до изменения сохранённых эталонов, запрещает дубли и недопустимые значения. При изменении текста создайте новый эталон. Эталон для другой версии чек-листа можно сохранить заранее, но сравнение с несовпадающей оценкой будет пропущено с объяснением.

Отчёт показывает точное совпадение значений по критериям, совпадение применимости N/A только для критериев, разрешающих N/A, отдельный результат по грубым ошибкам и среднюю абсолютную разницу итоговых баллов. Везде показаны знаменатели и покрытие. Нет ответа, устаревшие данные и несовпадение чек-листов не превращаются в нулевой балл или успешное совпадение. Если один из итогов не вычисляется из-за отсутствия применимых весов, пара исключается из средней разницы и учитывается отдельно. Это диагностические метрики, не официальная формула рейтинга хакатона.

### Учебная проверка полного сценария

Из карточки или раздела проверки создайте **учебную копию**. Она получает отдельный ID и источник `TEST`; исходные оценки, апелляции и аудиоссылки в неё не переносятся. Выберите сценарий или задайте ответы по критериям вручную, затем проверьте переход к реплике, подачу апелляции, решение проверяющего, пересчёт и историю повторных запусков.

Учебные ответы имеют `assessment.provider: "fixture"` и `testMode: true`. Реплики в них служат только для проверки переходов и не являются доказательством заданного значения. Модель не вызывается, смысл разговора не оценивается. Учебная точность доступна отдельно и проверяет только механику сравнения.

Учебные копии и их апелляции показываются в отдельном источнике. Они исключены из рабочих показателей и рабочего экспорта; экспорт учебных данных имеет отдельное имя и `scope: "test"`. Демонстрационные примеры также экспортируются отдельно. Как и остальные данные прототипа, эталоны и учебные сценарии хранятся в localStorage этого браузера; для резервной копии используйте экспорт.
